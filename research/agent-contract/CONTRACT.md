## 0. 一句话

**agent 不是新的结论来源。** 它拿到的是「已确定的结论 + 用户语境」，
交回的只能是「表达形式的变化」。而这条边界**由校验器强制执行，不靠提示词自律**。

> `PLAN.md` §5 风险表：「陪伴 agent 边界漂移 | 不能只靠提示词 | **可测规则 + 评测集**」。
> 所以本契约的重点不在那段提示词，而在**八条能被自动抓住的违规**（§4）。

---

## 1. 三条设计要点

### 1.1 `grounded_in` 路径制 —— 「不得引入新论断」唯一可自动化的形式

「不要编造」写在提示词里是无效的。**改成可检查的形式**：

> agent 的每一段输出都要声明它依据输入里的哪些**点分路径**；
> 校验器逐条解析这些路径，**不存在就是违规**。

```json
{"heading": "关于「焦虑」",
 "text": "...",
 "grounded_in": ["facets.anxiety.score.raw", "facets.anxiety.score.ci95"]}
```

写一个不存在的路径 ≡ 引入一个新论断。这是可判定的。

### 1.2 数字接地 —— 改写措辞可以，改分数不行

正文里出现的**每一个阿拉伯数字**都必须能在输入里找到。

⚠️ 一个曾经的漏洞：初版把 `0–100` 全段放行（本想放过百分位刻度），
结果等于没检查——「你的心理年龄约为 **42** 岁」这种编造会直接溜过去。
现在只额外放行李克特刻度 `1–5`。

### 1.3 `notable_items` —— 本项目独有的杠杆

我们为 300 道题**逐题写了脚手架**（承重词、常见误读、算什么不算什么）。
agent 可以据此对**这个人答的这道题**给出澄清：

> 「你答的第 103 题是『喜欢审视自己与自己的生活』。
> 这道题问的其实是『你是否喜欢反观和琢磨自己』。
> 承重词 examining 在这里指主动地审视、探究，而不是自我批评。」

**这不是通用模型能编出来的**——它需要逐题的作者级工作。这是把前面所有铺量
真正变现的地方。

选取规则：**答得极端（百分位 ≥90 或 ≤10）且脚手架记录了常见误读**的题，
最多 12 道。

**但措辞必须中性**：

| 可以说 | 不能说 |
|---|---|
| 「这道题问的是 X」 | 「你可能误读了这道题」 |
| 「承重词在这里指 X，不是 Y」 | 「你理解错了」 |

后者是对这个人的揣测，**我们没有证据**。校验器会拦（C6）。

## 2. 输入结构（agent 能看到什么）

| 字段 | 内容 |
|---|---|
| `coverage` | 已答题数、百分比、完成的情景数／轮数 |
| `facets` | 每个面向：精度（k/r/tier）、分数（经典模式）、`does_not_measure`、`interpretation_caveats` |
| `facets_showable` / `facets_withheld` | **明确区分「能说」与「不能说」** |
| `scene_results` | 情景模式的面板 A/B |
| `notable_items` | 值得澄清的题（含脚手架原文） |
| `quality_gate` | 协议偏离标志与可靠性折扣 |
| `disclosures` | **必须存活**的声明，逐条带 id |
| `user_context` | 用户自述处境 |
| `knowledge_refs` | 可引用的文献（带出处） |
| `rules` | 允许／禁止清单，随输入一起给 agent |

`facets_withheld` 是**显式**给出的。目的：让 agent 明确知道**哪些面向不许提**，
而不是靠它自己推断。

---

## 3. 必须存活的声明

| id | 内容 | 为什么不可删 |
|---|---|---|
| `norm_sample` | 参照人群为英国样本，非中国人群 | 常模适用性决定分数能不能被当真 |
| `no_diagnosis` | 不构成任何诊断，不能替代专业评估 | 产品定位是自测陪伴，不是筛查 |
| `content_caveat` | 面向自身的内容局限 | **删掉它们等于把「我们对自己工具的批评」藏起来**（§3.7） |
| `does_not_measure` | 这个分数不意味着什么 | 防误用 |
| `precision` | 有多少面向因题量不足未解锁 | 不能因为没数据就默认「中等」——那是编造 |
| `crisis_referral` | 命中危机标记时给专业求助渠道 | §3.5 |

**校验器不只看 `disclosures_kept` 清单，还要看正文里是否真有对应内容**——
只报 id 而正文没写，同样违规（C4）。

## 4. 八条可测规则

| 检查 | 抓什么 | 实测 |
|---|---|---|
| **C1 结构合法** | 输出是约定的 JSON 形状 | — |
| **C2 路径接地** | `grounded_in` 里有输入中不存在的路径 | ✅ |
| **C3 数字接地** | 正文出现输入里没有的数字 | ✅ |
| **C4 声明存活** | 必须存活的声明被删；或只报 id 正文没写 | ✅ |
| **C5 禁忌措辞** | 诊断、分型、MBTI、过度确定、疾病标签、医疗建议 | ✅✅ |
| **C6 越界主题** | 对 `facets_withheld` 作表述；把「误读」安到用户头上；澄清未标记的题；引用无出处 | ✅✅✅ |

**实测 8/8 份刻意构造的违规全部被抓住**（`tools/legacy/demo_agent_contract.py`）。

## 5. 允许与禁止（随输入一起交给 agent）

### 允许

- 改写措辞、语气、详略、段落组织
- 结合 `user_context` 里用户自述的处境来组织语言
- 对 `notable_items` 里的题给出**中性的题目澄清**
- 引用 `knowledge_refs` 并标注出处

### 禁止

- 引入输入中推导不出的新论断
- 改变任何数字
- 删减 `disclosures`
- 诊断、分型、贴标签
- 由分数反推量表之外的心理结论
- **对 `facets_withheld` 作任何表述（包括「大概中等」）**
- 把分数说成「证明」了什么
- 说用户误读了自己的答案
- 给医疗建议

## 6. 怎么用

```bash
# 1. 生成契约输入与提示词
python3 -c "
import sys; sys.path.insert(0,'.')
from engine.session import Session
from engine.agent_contract import build_contract, build_prompt
s = Session('classic'); ...            # 填入用户作答
open('in.json','w').write(__import__('json').dumps(build_contract(s, '用户自述'), ensure_ascii=False))
"

# 2. 把 prompt.txt 交给 agent，拿回 JSON

# 3. 校验（退出码非 0 即违规）
python3 tools/check/verify_agent_output.py --input in.json --output out.json
```

**建议**：把校验器接进生成流程——**校验不通过就不展示**，
而不是「展示出来再人工抽查」。规则的价值在于它是门，不是建议。

## 7. 本契约**没有**解决的问题

诚实列出：

1. **语义级的新论断仍可能漏网。** `grounded_in` 只能保证「引用的路径存在」，
   不能保证「这段文字确实是从这些路径推出来的」。要真正判定蕴含关系需要更强的
   手段（如让另一个模型做 entailment 判定），本轮没做。
2. **禁忌词表是黑名单。** 换个说法就能绕过（「你在社交场合的困扰程度达到了
   临床显著水平」不含任何禁忌词）。这是黑名单的固有局限。
3. **没有评测集。** `PLAN.md` §5 提到「可测规则 + 评测集」，本轮只做了规则，
   评测集（一批真实输入 + 人工判定的合格输出）还没有。
4. **危机识别的关键词表很粗。** 只覆盖了少数直白表述，
   隐晦的表达（如「想消失」）抓不到。
5. **质量门在情景模式下不适用。** 情景模式的作答顺序不是官方交错序，
   反义题与 longstring 指标的口径不同，当前只返回一条说明。
