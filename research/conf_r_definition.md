## 1. ① 答满时 `conf_r` 的解析含义：为什么不是 1

### 1.1 实现（逐行读过，不是转述）

`engine/inference.py:460-530` `dim_confidence()`：

```
492:  answered = [i for i in model.ids if i in coded]      # ← 用**全部已答题**（含别的维度）
500-509: 对每个已答题算 cᵢ：
           · 本维度的题 → cᵢ = item_dim_corr[i][dim]      # corrected：题 vs「其余题之和」
           · 别的维度的题 → cᵢ = Σⱼ sⱼρᵢⱼ / σ_T           # 普通相关（该题不在 T 里）
512-513: xb = solve(Σ_AA, c);   r_all = √(cᵀ Σ_AA⁻¹ c)
516-521: 只用本维度已答题 + b=item_dim_corr → r_own（**只作对照，不用于门控**）
```

`item_dim_corr` 的语义写在数据文件里（`data/inference/pid-5.json`）：
> `corrected（题与「其余题之和」的相关，**去本题**）——避免自解释使置信度虚高`

### 1.2 为什么它不等于 1（数学上）

若目标就是**该维度总分本身**，而预测变量是该维度的**全部题**，那么 `√(bᵀΣ⁻¹b)` 会**恰好等于 1**
——因为总分就是这些题的线性组合（这正是 `r2_total` 在答满维度的情形，见 §1.4）。

但判据口径刻意把**每道题的目标换成"去掉它自己之后的和"**（corrected）。于是：
* 每道题的**独特方差（测量误差）永远不被计入信息**；
* 剩下的只是"这道题的**共享**成分能提供多少信息"。
⇒ 量纲上它仍是 0–1 的 **信度型 / 可辨性** 量，但**上界严格小于 1**，除非题目之间完全相关（无独特方差）。

### 1.3 独立佐证一：合成单因子演示（脚本 §F）

`k=5`，`λ=√(1−ψ)`，`Σ = λλᵀ + diag(ψ)`（每题方差 1），按同一定义算 `√(bᵀΣ⁻¹b)`：

| ψ（每题独特方差占比） | 0.00 | 0.10 | 0.20 | 0.30 | 0.40 | 0.50 | 0.60 |
|---|---|---|---|---|---|---|---|
| `√(bᵀΣ⁻¹b)` | **1.0000** | 0.9756 | 0.9468 | 0.9121 | 0.8697 | 0.8165 | 0.7480 |

⇒ **只有当题目完全没有独特方差（ψ→0）时才趋近 1**；真实量表每题都有独特方差，
所以 PID-5 各维上限落在 **0.82–0.96**（§2.3）。**这就是"不是 1"的来源。**

### 1.4 独立佐证二：它只看"答了哪些题"，不看"答了什么"

| 检查 | 结果 |
|---|---|
| 全 0 作答 vs 全 3 作答（同一答题集合） | 逐维 `conf_r` **最大差 0.00e+00**（25 维） |
| 同一维的**预测分** | 全 0 → 0.75；全 3 → 2.25（**随作答值变**，而 `conf_r` 不变） |
| 只答本维度全部题：`r2_total` / 预测分 vs 官方分 | `r2_total = 1.0`；`1.75 == 1.75`（**得分精确**） |

⇒ `conf_r` 是**题目集合的信息量**，不是"你这次得分有多靠得住"。

### 1.5 对"我的理解"的判定

你的理解 **成立**，补两点：
1. **答满时它不只是"不等于 1"，而是恰好等于数据里的 `dim_ceiling_cross`**——那个值本来就是
   用「整卷答满」调出来的（§3），所以是**设计内的定点**，不是浮点噪声。
2. 更准确的说法不是"信度"（易与 Cronbach's α / 重测信度混淆），而是
   **"这套题对该特质的可辨上限"（identifiability ceiling）**：它回答"仅凭已答内容，
   这个特质最多能被定位到多准"，而不是"测量结果是否稳定"。文字表述见 §4。

## 2. ② `dim_ceiling` 与 `dim_ceiling_cross`

### 2.1 定义与生成代码

| 量 | 定义（运行时含义） | 生成处 | 落盘 |
|---|---|---|---|
| `dim_ceiling[d]` | **只答该维度全部题、一道别的维度的题都没答**时的 `conf_r` | `tools/build/build_dim_ceiling.py:226-236`：`A` 取该维度自己的题间相关子阵，`b` = corrected 题↔维度相关，`ceil[d]=round(√(bᵀA⁻¹b),4)` | `data/inference/<code>.json` |
| `dim_ceiling_cross[d]` | **整卷答满（全部题都答）**时的 `conf_r` | `tools/check/calibrate_conf_gate.py:144-159`：`coded = {i:0 for i in model.ids}` 后直接调 **运行时同一个** `dim_confidence()` | 同上（`--write`） |

数据文件里两段自带说明（原文）：
> `ceiling_note`：维度自身的置信度上限（**答满该维度的题时 r**，用 pairB64 的题间相关与 corrected 的题↔维度相关算出，与前端同源）。判据：当前置信度 ≥ ceiling × 0.9……
> `ceiling_cross_note`：跨维度上限：**整卷答满时的 conf_r**（本维度已答的题仍用 corrected 去本题、别的维度用与完整分的普通相关）。它**只是界面「已达上限的 X%」的分母**……

### 2.2 为什么答满时命中的是 cross 而不是 own

`dim_confidence()` 的预测变量是**全部已答题**（`engine/inference.py:492`）。
答满全卷时，除本维度的题以外，**别的维度的题也进了预测变量**（用它们与本维度总分的普通相关，
`:505-509`），信息更多 ⇒ `conf_r` 高于 own。
**判据门槛没有跟着变**：`available = conf_r ≥ dim_ceiling × ceiling_ratio(0.90)`，锚点仍是
**own**（`engine/inference.py:713-715`；数据里 `ceiling_ratio == ceiling_ratio_cross == 0.9`）。
cross 只做**显示分母**（`:706-708`）。

## 3. ③ "答满时 `conf_r == dim_ceiling_cross`" 是否自洽

**自洽；这是设计如此，不是 bug。** 三条证据：

1. **标定时说的就是"答满时的 r"**：
   * own 上限的注释写的是"答满**该维度**的题时 r"（`build_dim_ceiling.py:247-251` + 数据文件 `ceiling_note`）；
   * cross 上限写的是"**整卷答满时的 conf_r**"（`calibrate_conf_gate.py:145,167` + 数据文件 `ceiling_cross_note`）。
2. **标定代码直接调用运行时同一个函数**：`calibrate_conf_gate.py:152-155`
   `coded = {i: 0 for i in model.ids}` → `dim_confidence(model, dim, coded)["confidence_r"]`。
   所以落盘的 cross 与运行时的答满值**逐值同源**（实测 25 维最大差 4.82e-05，即 4 位小数舍入）。
3. **门槛口径没被这个分母改动**：`available` 仍锚 `dim_ceiling × 0.90`；`dim_ceiling_cross`
   只进 `ceiling_pct`（显示用）且被钳到 `[0,1]`（`engine/inference.py:706-708`；引擎测试
   "ceiling_pct 落在 [0,1]（不会显示 >100%）"通过）。

**⇒ 标定与运行时一致，没有"标的是 A、跑的是 B"的缺陷。**

**用户看到的问题属于"缺说明"，不属于"算错"**：导出报告给出的是
「估计分 = 1.75 / 置信度 r = 0.9307」，而该维度 8/8 题已答满——**分数其实已经精确**，
`r` 却在旁边显示 0.93，且那一节的口径说明是空的 `—`。§4 的文字就是补这一格。

## 4. ④ 可直接写进报告的「口径定义」文字

> **r 说的是"这套题能把你这项特质辨到什么程度"，不是"你这次得分有多准"**——它只取决于你**答了哪些题**，与你答出的具体分值无关。
> 只答了一部分时，r 随已答题数与贴题程度变化，我们要求达到该特质**可辨上限的九成**才会给出估计与位置；
> 把该特质的题**全部答完**时，分数已经是精确值（估计 = 官方计分、误差为 0），此时 r 停在**这套量表对该特质的可辨上限**（PID-5 各特质约 0.82–0.96），**因此不会、也不应该是 1**。

* 覆盖**答满**（第二句后半 + 第三句）与**未答满**（第二句前半）两种情形；
* 明确**不是"你这次得分的置信度"**（第一句 + "分数已经是精确值"）；
* **没有内部字段名**（不出现 `bᵀA⁻¹b` / `pairB64` / `ceiling_ratio` / `dim_ceiling` / `conf_r`）；
* 含"约 0.82–0.96"这一句是为了让读者看到 0.93 属于**正常上限**而不是异常读数。

（可选的一句更短版本，若版面紧张：「r 衡量的是**这套题对该特质的可辨程度**，只由"你答了哪些题"决定，不是你这次得分的可靠度；该特质的题答满时分数已精确，r 停在这套量表的可辨上限（约 0.82–0.96），所以不会到 1。」）

## 6. 存疑 / 观察（**与结论分开**，且**不含任何公式改动建议**）

1. **报告里的列名"置信度 r"是被误读的直接原因**：它紧挨「估计分」，而答满时分数其实已经精确
   （§1.4），读者自然会读成"我的答案只有 93% 可信"。这是**用户可见文案**问题，落在
   `frontend-infer` 的导出那一节；本报告 §4 提供了可直接替换的文字。**不改公式、不改门槛。**
2. **"已达上限 X%" 的分母是跨维度上限**，所以"本维度答满、别的维度没答"时该百分比**小于 100%**
   （引擎实测 pct=0.9487），只有**整卷答满**才 ≈100%（0.999972）。这个数本身没错，但如果同一节里
   出现"已达到 94.87%"，需要把分母（"整卷都答完时的上限"）一并说明，否则又是一个新的误读点。
3. **4 位小数舍入导致的 >100% 边界**：落盘的 cross 是 `round(…,4)`，而运行时 `conf_r` 未舍入，
   因此 `conf_r/cross` 可能极微大于 1（实测中位 1.000016）。显示路径已钳到 `[0,1]`，引擎测试
   也断言了这点，所以**不会**真的显示 >100%。如实记录，供文案节参考。
4. **`conf_r` 与答题顺序无关、与作答值无关**（§1.4）：如果将来有人把 r 的**升降**解释成
   "用户答得更好了"，那是误解——r 只在**题目集合变化**时变。**本轮不改任何东西**，仅登记。
